# AI security boundaries

Existing bearer authentication, account status, session revocation, administrator roles and company ownership are reused. Every conversation/message/feedback/cancellation route enforces owner access. Source access is enforced in SQL before retrieval and again at viewing/generation completion. Admin permissions allow knowledge management only within the caller's permitted scope; private sources have no blanket admin bypass.

PDFs, history and retrieved passages are untrusted. The fixed provider safety policy precedes editable assistant instructions and explicitly rejects document instructions to reveal secrets, change permissions, invent sources or invoke tools. No model tools are provided. Structured output and evidence validation constrain output. Adversarial PDF tests cover forbidden scope expansion and forged citations. These defenses are not a guarantee that all prompt injection or unsupported prose is impossible.

Original objects are private, immutable and version-specific. SHA-256 is checked by the worker, MIME/size/page/encryption/action gates reject unsuitable input, and object keys reject traversal. Downloads require authorization and expire after 60 seconds. Local tickets are purpose-bound, session-bound and checked against current access. Their query is redacted from the application access log; configure upstream/proxy logs to omit query strings as well. Signed S3 URLs remain bearer capabilities until expiry; do not log/share them. Flutter renders source images only from authenticated backend bytes and suppresses network images supplied through Markdown.

Server secrets stay in ignored local environments or deployment secret stores. No keys appear in settings responses or Flutter defines. No prompt/source contents are written to ordinary job/usage logs; errors are sanitized. Aggregate analytics does not expose identifiable conversations. Private content necessarily persists in the protected database/history/evidence snapshots. Restrict operational database, storage and backup access accordingly.

Daily request/token/upload limits, per-minute chat limits, provider timeouts, bounded contexts/output, batch size, connection caps and fenced jobs constrain abuse. Token/cost values are actual SDK usage when available; unknown prices remain unavailable. Failed or interrupted reservations can conservatively consume the daily budget. Quotas are per user, not a complete organization billing system.

Conversation retention uses explicit dry-run/execute maintenance. Archived originals are retained for historical evidence. No automatic paid infrastructure, production migration, public storage or external source scraping was performed. Before live use, review bucket/IAM/CORS, tenant membership provisioning, retention/backups and the real model's adversarial evaluation.
